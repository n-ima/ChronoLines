# 教訓ログ（learnings）

このプロジェクトの進行中に得られた「次から同じ失敗をしないための教訓」を1行ずつ追記する。
このファイルはセッション開始時にフックで自動的にエージェントへ注入されるため、
ここに書いたことは以後のすべてのセッションで前提として扱われる。

## 記録するタイミング（エージェント向けルール）

- ユーザーに同じ趣旨の訂正を受けたとき（1回でも記録してよい。2回目なら必ず記録する）。
- 同じアプローチで2回失敗したとき。
- プロジェクト固有の暗黙知（このリポジトリではXを使う、Yはしない等）が判明したとき。
- **コマンド・ツールの実行方法を試行錯誤の末に確立したとき**（成功したコマンドを
  そのまま記録する。実行方法の獲得知識は書かないと消え、次のセッションが
  同じ試行錯誤を繰り返す最大の原因になる。仕様の教訓より優先して書く）。
- セッションを終える・別フェーズへ引き継ぐ前に、このセッションで確立した
  環境固有の実行方法が記録済みか確認する（未記録のまま次へ渡さない）。

書式: `- [YYYY-MM-DD] <教訓を1行で。理由が自明でなければ括弧で補足>`
環境系の例: `- [YYYY-MM-DD] デプロイはCLIがPATHに無いため python -m <tool> で実行する`
Windows環境の例: `- [YYYY-MM-DD] cwdのドライブレターが小文字(d:\...)だとVitestがモジュール二重ロードでテスト全滅する。大文字(D:\...)へ cd してから npm scripts を実行する`

記録しないもの: 一般的なベストプラクティス（それはスキルに書く）、
一時的な作業メモ（それは各フェーズのドキュメントに書く）。

## 教訓

- [2026-08-12] vite dev サーバーは IPv6(::1) で listen するため、Playwright の page.goto や curl での疎通確認は `127.0.0.1:5173` ではなく `localhost:5173` を使う（127.0.0.1 直指定だと接続拒否になる）
- [2026-08-12] Git Bash から taskkill を使うときは引数変換を止めた上でスラッシュ1つ: `MSYS2_ARG_CONV_EXCL="*" taskkill /F /T /PID <pid>`（変換を止めずに `/F` だとパス変換で `F:/` に化け、変換を止めて `//F` だと literal `//F` のまま渡って「無効な引数」になる。2026-08-18 実測で訂正）
- [2026-08-18] dev サーバーを spawn する Node 検証スクリプトの出力を `| tail` へパイプしない（dev ツリーがパイプのハンドルを継承し、スクリプト終了後も tail が EOF 待ちでハングに見える。出力はリダイレクトかファイル書き出しにし、後始末の taskkill は spawnSync で完了を待ってから process.exit する。残留 dev ツリーを taskkill すると滞留出力が flush される）
- [2026-08-18] scratchpad に置いた Playwright 検証スクリプトは `createRequire(<プロジェクトの package.json>)` で `@playwright/test` を解決する（scratchpad はプロジェクト外のため素の import では解決できない）
- [2026-08-18] Playwright 検証でブラウザページを開いたまま dev サーバーを再起動しない（旧ページの自動保存リトライが新サーバーへ旧データを PUT して検証データを汚染する。サーバー停止前に必ず page/browser を閉じる）
