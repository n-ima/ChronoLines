# ADR 0001: 技術スタック（実行形態 = ローカルサーバー型、React + TypeScript）

- 日付: 2026-08-12
- ステータス: 承認済み（実行形態・UIフレームワークはユーザー選定。2026-08-12）

## コンテキスト

- 単一ユーザー・Windows PC・最新 Chrome/Edge でのローカル実行のみ。ホスティングなし・コスト0円（environment.md / nfr.md）。
- データはローカルにJSON形式で永続化し、アプリ更新をまたいで消えないことが最重要要件（US-009/010/011）。「更新するとデータが消える」は受け入れ不可。
- 人物1000人 × 年表範囲約3000年のグリッドを、初期表示3秒以内・操作応答100ms以内で描画する（nfr.md）。
- 要件定義の未確定事項 A-001（技術スタック・データ保存先の具体形）を確定させる決定。

## 検討した選択肢

| 選択肢 | メリット | デメリット |
|---|---|---|
| A: 純ブラウザSPA（静的ビルドのみ、保存 = IndexedDB） | 最速・最小構成。サーバー層のコードが不要 | データがブラウザプロファイル内に置かれ、「サイトデータ削除」で消える。配信ポート（=オリジン）が変わるとデータが見えなくなる罠。US-010 のデータ保全がブラウザ設定に依存する |
| B: ローカルサーバー型（Node.js 薄サーバー + SPA、保存 = ディスク上のJSONファイル） | データが目に見える実ファイルになり、ブラウザ設定・アプリ更新と構造的に分離される。ファイル直接コピーでのバックアップも可。既存リリースSkill（deploy-local-npx）に直結 | サーバー層の分だけ開発量が増える（小）。起動にコマンド1つ必要。常駐プロセスという新しい失敗モードを持ち込む（下記「結果・影響」） |
| C: デスクトップアプリ（Tauri v2 + SPA、保存 = AppData のJSONファイル） | 最もアプリらしい起動体験（exe）。ファイル保存も堅牢 | Rustツールチェーンの導入・ビルド学習コスト。更新のたびに exe 再ビルド・差し替え。リリースSkillの新規作成が必要。個人ツールとしては過剰投資 |

## 決定

**選択肢 B（ローカルサーバー型）** を採用する（ユーザー選定。2026-08-12）。

このアプリの核心リスクは描画性能（3案で差がない）ではなくデータ保全であり、
「ブラウザのサイトデータ削除で長期蓄積したデータが消える」事故を構造的に排除できる
B が要件適合度で最も高い。開発量の増分（読み書きAPI 3本程度の薄いサーバー）は小さい。

技術スタックの内訳（フレームワーク選定はユーザー確認済み、ライブラリ選定はエージェント判断）:

| 領域 | 選定 | 理由 |
|---|---|---|
| 言語 | TypeScript（クライアント・サーバー・共有ドメインロジックすべて） | 年齢計算・スキーマ移行など仕様の核心を型で守る。単一言語でクライアント/サーバー間のコード共有（バリデーション・移行ロジック）が可能 |
| UIフレームワーク | React 19 + Vite | ユーザー選定。エコシステム・情報量が最大で、全自動の実装フェーズで最も安定して書ける |
| サーバー | Node.js 22+ / Express 4 | 3エンドポイント程度の静的配信+JSON読み書きAPI。最も情報量が多く枯れている |
| 状態管理 | Zustand | セレクタ購読で不要な再レンダリングを避けられる（1000行グリッドの性能要件に適合）。Redux は本規模には過剰 |
| グリッド仮想描画 | @tanstack/react-virtual | ADR 0003 参照 |
| スキーマ検証 | Zod | 保存データ・インポートJSONの実行時検証（US-010/011、NFRのスキーマ検証要件）。TypeScript 型と単一ソースで一致させられる |
| スタイリング | CSS Modules | ビルド追加依存なし・実装が迷わない。デザイントークンは CSS カスタムプロパティで共有（docs/02-design/ui/design-tokens.md） |
| テスト | Vitest（単体）+ Playwright（E2E, Chrome/Edge） | ドメインロジック（年齢計算・移行）の単体テストと、主要フローのE2E。詳細はテストフェーズで計画 |

## 結果・影響

- 捨てたもの: exe ダブルクリック起動（C）。起動は `npm start`（またはリリース時に定義する起動スクリプト）1コマンドになる。利用者は開発者本人のため許容。
- リリース手段は `deploy-local-npx` スキル（npm ci → build → 起動確認 → タグ固定）をベースにできる。CI/CD は使わない（environment.md）。
- **新しい失敗モード = ローカル常駐プロセス（サーバー）を持ち込む。劣化時の受け皿を次のとおり定める**:
  - 起動失敗（ポート衝突）: 既定ポート 5177。使用中なら起動時に明確なエラーメッセージ（使用中ポートと変更方法）を表示して終了する。ポートは環境変数 `CHRONOLINES_PORT` で変更可能。
  - サーバー突然死・接続断: クライアントは保存API失敗時にエラーバナーを表示し、未保存の変更をメモリに保持したまま再試行できる。クライアント側のみでJSONエクスポート（ブラウザダウンロード）が可能な設計とし、サーバー死亡時でも表示中データの退避手段を残す（詳細設計 server-api.md 5章 / ui-timeline-grid.md 9章 / ui-forms-dialogs.md 4章）。
  - 書き込み失敗（ディスク・権限）: 保存失敗をユーザーに通知し、直前の正常ファイルを .bak として保全する（ADR 0002）。
  - エラー境界: React のルートエラーバウンダリで捕捉し、白画面ではなくエラー表示+エクスポート導線を出す。
- Node.js のメジャー更新・依存ライブラリの更新はデータ形式に影響しない（データ互換は schemaVersion で管理。ADR 0002）。
