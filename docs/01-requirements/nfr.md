# 非機能要件（NFR）

単一ユーザー・ローカル実行のアプリのため、サーバー運用系の項目は「該当なし」が多い。
性能・スケール・データ保全がこのアプリの主要な非機能要件である。

| 区分 | 要件 | 目標値・基準 | 備考 |
|---|---|---|---|
| 性能 | 初期表示 | 人物1000人・イベント総量5000件（A-003の想定総量）・年表範囲3000年分（紀元前1000年〜現在）のデータを読み込んだ状態で、起動から年表の初期表示まで3秒以内（開発機相当のPC） | 品質特性シナリオ形式。リリース前に実測して見直す |
| 性能 | 操作応答 | 同データ量で、スクロール・ズーム切り替え・検索・絞り込みの操作応答が100ミリ秒以内（体感で引っかからない） | 仮想描画等の実現手段は設計で決定 |
| 性能 | 同時アクセス数 | 該当なし（単一ユーザー・ローカル実行） | |
| 可用性 | 稼働率目標 | 該当なし（ローカルアプリ。ユーザーが起動したときに動けばよい） | |
| 可用性 | 障害時の復旧目標(RTO/RPO) | 復旧はJSONインポートによる手動リストア。RPO = 最後に手動エクスポートした時点 | US-011 が復旧手段 |
| セキュリティ | 認証・認可方式 | 該当なし（ローカル・個人利用。ログイン機能は作らない） | スコープ外に明記済み |
| セキュリティ | データ保護（暗号化等） | 保存データの暗号化は行わない（ローカルPC内に留まり外部送信しない）。ネットワーク送信機能を持たないこと自体を要件とする | |
| セキュリティ | OWASP Top10相当の考慮 | ユーザー入力（人物名・イベント名・メモ）の表示時エスケープ（XSS対策）。インポートJSONのスキーマ検証（不正データで壊れない。US-011） | ローカルアプリでも入力値検証は境界（インポート・フォーム）で行う |
| 運用・監視 | ログ・監視方針 | 該当なし（監視は行わない）。エラー発生時は画面上でユーザーに内容を通知する | |
| 運用・監視 | バックアップ方針 | 手動のJSONエクスポートで行う（自動バックアップは作らない） | US-011 |
| スケーラビリティ | 想定データ量・成長見込み | 人物: 1000人（上限は設けない）。年表: 10個程度。イベント: 1年あたり最大100件・総量5000件までを性能保証範囲とする（A-003 を2026-08-12に確定。登録自体の上限は設けない） | 性能目標の前提値 |
| 対応環境 | 対応OS/ブラウザ/デバイス | Windows PC の最新版 Chrome / Edge で動作すること。スマートフォンは表示できれば十分（最適化しない） | 実行形態（ブラウザ/デスクトップ）は設計で決定（A-001） |
| コスト | インフラ・運用コスト上限 | 0円（ホスティング・外部サービスを使わない） | |
| コンプライアンス | 法規制・社内ポリシー | 該当なし（個人利用・個人データは本人管理） | |
| アクセシビリティ | 対応レベル | 特段の要件なし。基本配慮のみ（生存中/没後の色区別は色だけに依存させず、コントラストを確保する） | 色覚多様性への最低限の配慮 |
| 国際化 | 多言語対応の要否 | 不要（日本語のみ）。年表記は西暦のみ・紀元前は「前500」形式 | スコープ外に明記済み |
