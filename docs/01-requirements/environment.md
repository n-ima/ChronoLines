# 環境・リリース自動化情報

このファイルは、リリースフェーズを自動実行するために **必須の入力** になる。
（2026-08-12 ユーザーヒアリングで確定。仮置きなし）

## デプロイ先

| 項目 | 内容 |
|---|---|
| ホスティング/実行環境 | なし（ホスティングしない）。ユーザー本人の Windows PC 上でのローカル実行のみ |
| リージョン・ドメイン | 該当なし |
| CI/CDの有無・利用サービス（GitHub Actions等） | なし。GitHub Actions も使わない（テスト・ビルドはローカルで実行する）。リポジトリは GitHub（このリポジトリ）にソース管理のみ行う |
| コンテナ/オーケストレーション | 該当なし |

## 認証・認可・シークレット

| 項目 | 内容 |
|---|---|
| デプロイに必要な認証情報の種類 | 該当なし（デプロイ先がない。GitHub への push はユーザーの既存 Git 資格情報を使う） |
| シークレットの保管場所 | 該当なし |
| エージェントがアクセス可能な範囲 / アクセスできないもの | 秘密情報は扱わない。エージェントはリポジトリ内のファイルのみ操作する |

## 自動化できる/できない境界

| 作業 | 自動化可否 | 理由・人手が必要な場合の担当 |
|---|---|---|
| ビルド・パッケージング | 自動 | ローカルで実行 |
| テスト実行 | 自動 | ローカルで実行 |
| デプロイ（インフラへの反映） | 該当なし | デプロイ先がない。「リリース」= ローカルで起動確認済みの配布可能な状態を作り、バージョンを固定すること |
| DBマイグレーション | 該当なし（外部DBなし） | 保存データのスキーマ移行はアプリ自身が起動時に自動実行する（US-010） |
| 監視・アラート設定 | 該当なし | 監視しない（nfr.md） |
| 本番切り替え（カットオーバー） | 該当なし | 本番環境がない |
| git commit | 自動 | ハーネス既定どおり |
| git push・タグ付け | 人手（毎回ユーザー確認） | ハーネス既定どおり。エージェントはコマンドを提示しユーザーが実行を承認する |

## 利用者の運用作業の自動化境界（配布型アプリでは省略不可）

利用者 = 開発者本人のみ。それでも更新時のデータ保全は必須要件とする（US-010）。

| 利用者の作業 | 自動 / 手作業 | 備考（スクリプト提供の有無等） |
|---|---|---|
| 初期導入（インストール） | 手作業（簡単な手順であること） | 具体的手順は設計の技術選定（A-001）後に確定し、README に記載する |
| バージョン更新（2回目以降のインストール） | 手作業。ただし**データの引き継ぎは自動**（必須） | 保存データは配布物と分離し、更新後の初回起動でスキーマ自動移行する（US-010）。「更新するとデータが消える」は受け入れ不可 |
| バックアップ | 手作業（JSONエクスポート） | 自動バックアップは作らない（US-011） |
| 復旧（リストア） | 手作業（JSONインポート） | US-011 の受け入れ条件が復旧手順を兼ねる |

## ロールバック方針

- 失敗時にどこまで自動でロールバックしてよいか:
  外部環境がないため「ロールバック」= 旧バージョンのアプリに戻すこと。Git のタグ/コミットから
  旧版を取り出して差し替える（手作業）。保存データは US-010 の後方互換により旧版でも
  読めるとは限らないため、更新前のJSONエクスポートを推奨手順に含める。
- 人手でのロールバック判断が必要なケース: すべて（自動ロールバックの仕組みは作らない）。

## この環境向けの既存Skillの有無

- 該当する既存Skill: 候補として `deploy-local-npx`（ローカル起動確認 + タグでのバージョン固定）
  および `deploy-local-zip`（Gitタグ + ZIP配布）がハーネスに収録済み。
  どちらを使うか（または新規作成するか）は、設計フェーズの技術選定（A-001）で
  実行形態が決まった後、リリースフェーズで確定する。
