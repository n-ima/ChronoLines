# ChronoLines

歴史上の人物の「生きている時間」を横方向の年表として並べ、あるイベントの時点で
それぞれの人物が何歳だったかを一目で比較できるアプリです。

- 例: 「関ヶ原の戦い（1600年）のとき、徳川家康は57歳、伊達政宗は33歳」が1画面で分かる。
- 自分の PC の中だけで動くローカルアプリです。サーバーは `127.0.0.1`（自分の PC）でのみ
  待ち受け、データを外部に送信することは一切ありません。
- データは PC 内の JSON ファイル1つに保存されます（場所は「データファイルの場所」参照）。

主な機能: 複数年表の管理 / 人物・イベントの追加・編集 / 紀元前（前N年）対応 /
タグでの絞り込み・人物検索 / JSON エクスポート・インポート（バックアップ・復旧）/
年表の PNG 画像出力。

## 必要環境

- Node.js **22 以上**（npm 同梱）
- 動作確認は Windows で行っています（保存先の既定パスなど Windows 前提の説明があります。
  macOS / Linux でも動作する設計です）

## インストール

```powershell
git clone <このリポジトリのURL>
cd ChronoLines
npm ci
```

2回目以降（バージョン更新時）も同じ `npm ci` を使います（後述の「バージョン更新の手順」参照）。

## 起動

```powershell
npm start
```

- 初回（`dist/client` が無いとき）は自動でビルドしてからサーバーを起動します
  （十数秒程度。2回目以降はビルド済みの `dist/client` をそのまま配信して即起動します）。
- 起動に成功するとコンソールに URL とデータファイルのパスが表示されます。
  ブラウザで **<http://localhost:5177>**（= `http://127.0.0.1:5177`）を開いてください。
- 停止はコンソールで `Ctrl+C`。編集内容は操作のたびに自動保存されているので、
  そのまま止めて問題ありません。
- 「ポート5177が使用中です」と表示された場合: 既に起動済みの ChronoLines を終了するか、
  環境変数 `CHRONOLINES_PORT` で別ポートを指定してください。

## データファイルの場所

保存データはアプリのフォルダ（このリポジトリ）とは**別の場所**に置かれます。
アプリの更新・入れ替え・`git clean` をしてもデータには触れません。

| 優先順位 | 場所 |
|---|---|
| 1. 環境変数 `CHRONOLINES_DATA_DIR` が設定されているとき | そのフォルダ |
| 2. 未設定のとき（Windows） | `%LOCALAPPDATA%\ChronoLines`（例: `C:\Users\<ユーザー名>\AppData\Local\ChronoLines`） |
| 3. 未設定のとき（macOS / Linux） | `~/.local/share/chronolines` |

フォルダ内のファイル:

| ファイル | 役割 |
|---|---|
| `chronolines.json` | 保存データ本体（全年表を含む単一 JSON。手動でコピーしてもよい） |
| `chronolines.json.bak` | 直前の正常版（保存のたびに1世代残す。手動復旧用） |
| `chronolines.v<N>.bak` | バージョン更新でデータ形式を自動移行する直前の旧形式データ |
| `chronolines.corrupt-<日時>.json` | 壊れていて読めなかったファイルの退避（黙って捨てない） |

## バージョン更新の手順（2回目以降のインストール）

1. **更新前に JSON エクスポートを取る（推奨）**: ツールバー〔入出力〕→「エクスポート」タブ →
   範囲「すべての年表」でダウンロードし、保管する（旧バージョンへ戻すときに必要になります）。
2. 新しいバージョンを取得する: `git pull`（またはリリースタグを checkout）。
3. `npm ci` で依存関係を入れ直す。
4. `npm run build` で再ビルドする（**`npm start` はビルド済みの `dist/client` があると
   そのまま使うため、更新後は明示的に再ビルドが必要です**）。
5. `npm start` で起動する。

**データの引き継ぎは自動です。** 保存データはアプリと分離されており、更新で消えることは
ありません。データ形式（`schemaVersion`）が変わる更新では、更新後の初回起動時にアプリが
自動で新形式へ移行します。移行の直前に旧形式のファイルを `chronolines.v<旧版>.bak` として
保全するため、移行で元データが失われることもありません。

- 逆に、**新しいバージョンのアプリで保存したデータを古いアプリで開いた場合**は、
  データを上書きせずに停止し、ブラウザに読み取り専用の案内（リカバリ画面）を表示します。
- 旧バージョンへ戻す（ロールバック）場合: Git のタグ/コミットから旧版を取り出して
  `npm ci` → `npm run build` → `npm start` し、手順1で取っておいたエクスポート JSON を
  インポートして復旧します（新形式のままのデータは旧版では読めないことがあるため）。

## バックアップと復旧

自動バックアップ機能はありません。バックアップは手動の JSON エクスポートで行います。

### バックアップ（エクスポート）

1. ツールバーの〔入出力〕→「エクスポート」タブを開く。
2. 範囲を選ぶ（「現在の年表のみ」/「すべての年表」）。
3. ダウンロードされた `chronolines-export-YYYYMMDD-HHmm.json` を安全な場所に保管する。

エクスポートはブラウザ内だけで完結するため、万一サーバー側で保存に失敗している状態でも
画面に見えているデータを退避できます。

### 復旧（インポート）

1. ツールバーの〔入出力〕→「インポート」タブを開く。
2. エクスポートした JSON ファイルを選ぶ（保存データ本体 `chronolines.json` の
   コピーもそのまま読み込めます）。
3. 取り込み方法を選んで〔取り込む〕:
   - 「すべて置き換える」= 現在のデータをファイル内容で置き換える（確認あり。復旧用）
   - 「年表として追加」= ファイル内の年表を現在のデータに追加する
4. ファイルが壊れている・形式が新しすぎる場合は取り込みを拒否し、
   **既存データには一切触れません**。

### 起動時にデータが読めない場合（リカバリ画面）

保存データが壊れている等で読み込めない場合も、アプリは**データを初期化せず**に起動し、
ブラウザにリカバリ画面を表示します。画面の案内に従って次のいずれかで復旧します。

- **JSONファイルから復旧** — エクスポート済みのバックアップを取り込む。
- **自動バックアップから手動復旧** — データフォルダの `chronolines.json.bak`（直前の正常版）を
  `chronolines.json` に上書きコピーし、サーバーを再起動して〔再試行〕。
- **空のデータで開始** — バックアップが無い場合の最終手段（確認あり）。

読めなかった元ファイルは、新しいデータを保存する時点で
`chronolines.corrupt-<日時>.json` として同じフォルダに退避されます（黙って捨てません）。

## 開発者向け

```powershell
npm run dev        # 開発モード（Vite: http://localhost:5173 + API サーバー 5177 を同時起動）
npm test           # 単体テスト（Vitest）
npm run test:e2e   # E2E テスト（Playwright）
npm run typecheck  # 型チェック
npm run build      # 型チェック + 本番ビルド（dist/client）
```

要件・設計・テストのドキュメントは [docs/](docs/) 配下にあります
